## Critical  

| # | Code / Behaviour | Why it is a problem (impact on stability / usability) | Confidence | Fix / Mitigation |
|---|------------------|------------------------------------------------------|------------|-------------------|
| C1 | **`SetWinEventHook` delegate lifetime** – `SetWinEventHook(..., WinEventProc proc, …)` stores the delegate only in the call‑stack. The delegate is not kept in a static field, so the GC can collect it while the hook is still active. Once collected the hook stops firing, leaving the **focus‑tracker dead** and the app will report *“窗口不支持朗读”* even though the target window is still focused. | Random loss of hot‑key / click‑trigger functionality, especially after the user has been idle for a while (GC runs). | Keep the delegate alive for the whole lifetime of the hook, e.g. `private static readonly WinEventProc _hookProc = HookCallback;` and store the returned hook handle in a field that is disposed on shutdown. |
| C2 | **Missing `IsWindow`, `GetForegroundWindow`, `SetForegroundWindow`, `GetWindowThreadProcessId` imports** – they are used in `ThreadFocusOf`, `RestoreForegroundAsync`, `IntegrityLevelOf` etc. If they are not declared elsewhere the project will not compile; if they are declared elsewhere with a different signature the calls may be marshalled incorrectly, leading to **access‑violation crashes** on 64‑bit Windows. | Build‑time failure or runtime crashes on the very first UI‑A call, which is fatal for a beginner‑user product. | Verify that the P/Invoke signatures exactly match the Win32 API (use `uint` for thread IDs, `IntPtr` for HWND, `bool` return). Keep all native imports in a single static class to avoid duplication. |
| C3 | **`UpdateLayeredWindow` usage** – the `BLENDFUNCTION` struct is passed by reference but the fields are never initialised (`SourceConstantAlpha` and `AlphaFormat`). The default value of `AlphaFormat` is `0` (AC_SRC_OVER) which tells the system that the source bitmap has **no per‑pixel alpha**. The result is a completely transparent ball or a solid‑colour block, depending on the HDC contents. | The mascot may be invisible or draw a solid rectangle, breaking the core UI for users with visual impairments. | Initialise the struct: `pblend = new BLENDFUNCTION { BlendOp = AC_SRC_OVER, SourceConstantAlpha = 255, AlphaFormat = AC_SRC_ALPHA };` before calling `UpdateLayeredWindow`. |
| C4 | **`WaitModifiersReleasedAsync` uses `keybd_event` with VK 0xE8** – 0xE8 is not a documented virtual‑key code. On many keyboards it maps to an undefined key and can generate **spurious key‑presses** that appear in the target application (e.g. a stray character in a text editor). | Users may see unexpected characters inserted when the app tries to clear modifiers, which is especially confusing for the eye‑condition audience. | Replace the fake‑key trick with a proper `SendInput` call that only releases the modifier keys that are actually down, or simply ignore the “stuck Alt” case (the OS already dismisses the system menu after a short timeout). |
| C5 | **`RestoreForegroundAsync` does not call `AllowSetForegroundWindow`** before `SetForegroundWindow`. When the target window runs at a higher integrity level (e.g. an elevated editor) the call silently fails, leaving the app unable to bring the target to the foreground after a click‑trigger. This is exactly the symptom reported for hot‑key activation when the user has an elevated editor open. | Hot‑key activation fails intermittently, producing the *“窗口不支持朗读”* message even though the target is correct. | Call `AllowSetForegroundWindow(pidOfTarget)` (or `ASFW_ANY`) **before** `SetForegroundWindow`. Also check the return value of `SetForegroundWindow` and fall back to `SwitchToThisWindow` on failure. |
| C6 | **`IntegrityLevelOf` returns raw RID values** (e.g. `0x00002000` for Medium) but callers compare them to `0`/`1` etc. Without normalising the value the check may treat a Medium‑IL process as “high” and incorrectly display the *“run as administrator”* warning, or miss a real elevation. | Users may be shown unnecessary elevation prompts, or the app may silently refuse to work with elevated targets. | Normalise the integrity level: `int level = (int)Math.Log(value, 0x1000); // 0=Untrusted,1=Low,2=Medium,3=High,4=System` or compare against the documented constants (`SECURITY_MANDATORY_MEDIUM_RID`, etc.). |
| C7 | **`SetWinEventHook` flags omit `WINEVENT_INCONTEXT`** – the hook runs out‑of‑context, which is fine, but the callback runs on a **thread‑pool thread** with **no COM apartment initialisation**.
