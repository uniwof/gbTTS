# Android v0.5 外部审查与辩论纪要（2026-10-15）

审查模型：NVIDIA API 上的 stepfun-ai/step-5-preview、nvidia/nemotron-3-ultra-550b-a55b。
要求：不要附和我、也不要附和用户，客观挑毛病。长提示词时 nemotron 两次 504，改为按模块拆成 4 份（设计 / 播放器 / 无障碍 / 音色包）。
原始回复：review/r1/r2*_*.txt、r3*_*.txt；我的反驳：review/r1/reb.json；对方再反驳：r4_*.txt。

## 采纳（已改进代码）
1. start() 的“停旧 + 开新”放进同一把锁（两路声音重叠的隐患）。
2. stop() 只 pause() 打断写入；flush/stop/release 由合成线程自己在 finally 里做（不跨线程操作 AudioTrack）。
3. AudioTrack 写出错时显示“声音输出出错”；minBuf 异常兜底；缓冲 1 秒 → 2 秒。
4. 播完判断改成 32 位回绕安全比较。
5. 文本清理/切分移到后台线程；超过 10 万字提示“只读前 10 万字”。
6. 按键：新的 DOWN 清掉待吞的 UP；按住重复不重复触发；只认实体键盘（虚拟键盘注入的不算）。
7. 悬浮条拖动按实际宽高限制，整条留在屏幕内。
8. 找选区时跳过输入法、状态栏/导航栏窗口。
9. 新增：订阅“选中文字”事件，只在内存里记最近一次（不跨进程、不复制，按开始时才截取，2 分钟有效、最多 10 万字、密码框不记）。
10. zip 导入：上限 = min(3 GB, 剩余空间 − 200 MB)；canonicalPath 双保险；256 KB 缓冲；进度每 20 MB。
11. 导入：先装到 .part- 临时文件夹，校验通过再改名（原子）；整批只扫描一次；主模型凭模型指纹硬链接，其它大文件全量比对；同内置模型的包只存 voice.json + 样音，builtin_model.txt 记“模型指纹”；空间预检按实际写入量并预留 200 MB；SAF 读不到文件直接报错；/* 注释未闭合报错；builtins() 加锁。
12. Lint 发现并修复：`List.forEach`（API 24）在 Android 6 上会崩 → 改 for 循环。

## 驳回（附理由，对方再反驳后仍维持）
- 无障碍节点不 recycle “会耗尽池子返回 null 崩溃”：obtain() 池空时新建对象，不会返回 null；不回收只是少复用。
- 无障碍触发时后台启动前台服务被禁：官方文档把“能从后台启动 Activity 的应用”列为豁免，系统绑定的无障碍服务属于此类；且失败已 try/catch，照常朗读。
- 合成时持有状态锁导致 ANR：合成不在 synchronized(lock) 内，wait() 会释放锁。
- toggle 顺序问题：标志和 pause/play 在同一个 synchronized 里。
- safeRel 能被 a/../../ 绕过：任何 “..” 段都拒绝，另有 canonicalPath 检查。
- 取消“全音色版”：用户 2026-10-13 明确要求安卓出“全内置 + 精简”两种。
- 系统 TTS 没有标点停顿：引擎里同样逐句插入停顿（审查方没看到 CaretTtsService）。
- PROCESS_TEXT 只在可编辑文字出现（step-5 坚持）：nemotron 同意我的看法；Android 本身有 EXTRA_PROCESS_TEXT_READONLY，Chrome 只读选区也会出现第三方项。
- 输入框拿不到光标时读整个输入框：这是最接近 Windows 的行为。

## 仍有分歧 / 已知风险
- 多音字前端约 105 MB Java 堆（largeHeap）。少数机型 largeHeap 只有 256 MB，仍够用但余量小；OOM 时自动退回“不纠正多音字”（仍有声音）。以后可改成二进制 Trie / mmap 降内存。
- 未在真机或模拟器运行（沙盒是 ARM64、无 KVM）。
- 未做：导出诊断日志按钮；通知栏自绘图标。
